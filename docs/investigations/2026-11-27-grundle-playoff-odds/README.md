# Grundle playoff odds: verification and race check (2026-11-27)

Context behind the Playoffs and Bye odds on Standings and the Playoffs race panels (release `2.8.0`, branch `release/2.8.0`). It records how the numbers were checked, what Codex found when it reviewed them, and where the maintainer's team, **The Sweater Song**, stood after week 11.

Each figure is labeled:

- **REAL**: the live Sleeper API, saved in [sleeper-snapshot.json](sleeper-snapshot.json), or the checked-in Sister League snapshot.
- **SYNTHETIC**: generated by tests or scripts.
- **USER-REPORTED**: read by the maintainer from the Sleeper app or another site. The Sleeper API does not provide these.

The snapshot keeps only team names, divisions, records, points, weekly scores, and pairings. It has no user ids, owner names, avatars, or lineups.

## What the feature does

- **Model.** The Sister League's Monte Carlo model is now shared in [seasonSimulation.ts](../../../frontend/src/utils/seasonSimulation.ts):
  - Each team scores Normal(mean, sd) every week.
  - The mean is the team's average, shrunk toward the league average by 2 weeks: `(n*teamMean + 2*leagueMean)/(n+2)`.
  - The sd is the team's own, floored at half the league sd.
  - There are 10,000 runs with a fixed seed.
- **Grundle seeding.** [grundleOdds.ts](../../../frontend/src/utils/grundleOdds.ts) seeds every simulated finish under the `computeSeeds` rules (constitution section 11):
  - Seeds 1-3 go to the division winners.
  - Seeds 4-5 go to the next best records.
  - Seed 6 goes to the highest points-for among everyone else.
  - Records count wins only, and ties are ignored.
- **When odds are withheld.** Unless Sleeper returns every completed score and a pairing for every remaining game, the cells show `-`.
- **Display.** 100% and 0% appear only when the schedule-aware best/worst range has settled the cut. Otherwise the cells show `>99%`, `<1%`, or a rounded percent.
- **Known gap.** A week in progress counts as unplayed. Live points are ignored.

## Real-time updates: not pursued

- **Live B-W.** B-W is win/loss only, so live points cannot move it until a game is decided. The only honest version would lock in games where every starter has finished. That would need the large `/players/nfl` map and the ESPN scoreboard on Standings, stat corrections remain a risk, and it gains little before Sleeper processes the week.
- **Live percentages.** These would need each team's remaining starters and their projections. Scaling a team's average by its unfinished starters would treat a Monday-night quarterback like a kicker who has already played. [ROADMAP.md](../../../ROADMAP.md#projected-totals-and-win-probability) already gates win probability on a defensible projection model.
- **Decision.** The maintainer agreed not to build either.
